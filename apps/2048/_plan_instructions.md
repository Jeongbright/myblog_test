# Plan 서브에이전트 작업 지시서

## 목적
사용자가 요청한 웹앱: "2048 게임" — 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임, 점수판 포함.

## 프로젝트 컨텍스트
- 이 저장소(`my_blog`)는 마크다운 블로그 + 미니 웹앱 포트폴리오. 저장소 루트의 `CLAUDE.md`를 먼저 읽고 규칙을 파악할 것.
- 웹앱은 `/apps/2048/` 폴더 안에 독립적으로 만들어야 하며, 블로그의 다른 파일(`index.html`, `css/`, `js/`, `posts/` 등)은 건드리지 않는다.
- 프레임워크 없이 순수 HTML/CSS/JS. 외부 라이브러리는 최소화한다 (CDN은 허용되지만 이 게임에는 불필요할 가능성이 높다).
- 모바일에서도 사용 가능해야 한다 (터치 스와이프 등 고려).

## 해야 할 일
1. `apps/2048/` 폴더에 들어갈 파일 구조를 설계한다 (예: `index.html`, `style.css`, `script.js`).
2. 게임 로직을 어떻게 구현할지 정리한다:
   - 4x4 격자, 시작 시 타일 2개 랜덤 생성(2 또는 4)
   - 방향키(↑↓←→) 입력으로 타일 이동/병합 규칙
   - 병합 시 점수 계산 방식과 점수판 UI
   - 이동 후 새 타일 랜덤 생성 조건
   - 게임 오버(더 이상 이동/병합 불가) 판정 로직
   - 2048 타일 등장 시 승리 처리 방식 (계속하기 허용 여부 등)
   - 재시작 버튼
   - 모바일 터치(스와이프) 처리 방식
3. UI/디자인 방향을 간단히 정리한다 (색상, 레이아웃, 반응형 방식). 블로그 메인 페이지의 기존 톤(`css/style.css`의 라이트/다크 테마)과 크게 어긋나지 않아도 되지만, 앱은 독립적이므로 자체 스타일을 가져도 된다.
4. 위 내용을 종합해 `apps/2048/spec.md` 파일로 저장한다. `spec.md`는 이후 별도의 Build 서브에이전트가 그대로 구현 지침으로 사용하므로, 파일별로 무엇을 넣을지 최대한 구체적으로 적는다 (함수/상태 구조, DOM 구조, 이벤트 처리 흐름 등).

## 하지 말아야 할 것
- 실제 코드(`index.html`, `script.js` 등)를 작성하지 않는다. 이번 단계는 계획(`spec.md`)만 작성한다.
- 블로그의 다른 파일을 수정하지 않는다.

## 완료 조건
`apps/2048/spec.md` 파일이 작성되면 작업 완료. 완료 후 spec의 핵심 요약을 간단히 보고할 것.
