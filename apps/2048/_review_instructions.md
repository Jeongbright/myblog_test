# Review 서브에이전트 작업 지시서

## 목적
`apps/2048/` 안에 구현된 2048 게임(`index.html`, `style.css`, `script.js`)을 `spec.md` 기준으로 검증하고, 결과를 `review.md`로 남긴다.

## 범위
- 검토 대상: `apps/2048/index.html`, `apps/2048/style.css`, `apps/2048/script.js`
- 비교 기준: `apps/2048/spec.md`
- 문제를 발견하면 `apps/2048/` 안의 위 3개 파일만 직접 수정해서 고친다. 그 외 블로그 파일은 건드리지 않는다.
- 산출물 `apps/2048/review.md`를 새로 작성한다.

## 해야 할 일
1. `apps/2048/spec.md`를 읽고 기대 동작(핵심 함수, 이벤트 흐름, 판정 로직)을 파악한다.
2. `index.html`, `style.css`, `script.js` 코드를 정독하며 다음을 점검한다:
   - 문법 오류나 명백한 런타임 버그가 없는지 (예: 참조 오류, undefined 접근)
   - 4방향 이동/병합 로직이 올바른지, 특히 3연쇄 병합(`[2,2,2,2]` 등) 같은 엣지 케이스 처리
   - 게임 오버 판정이 정확한지 (빈 칸 없고 인접 병합도 불가능할 때만 오버)
   - 점수/최고점수 계산과 localStorage 저장이 올바른지, 프라이빗 모드(저장 실패) 상황에서도 에러 없이 동작하는지
   - 키보드(방향키) 입력과 모바일 터치 스와이프 입력이 둘 다 구현되어 있는지
   - 모바일 폭에서 레이아웃이 깨지지 않는지 (반응형)
   - 다크모드(`prefers-color-scheme`)가 적용되는지
3. 실제로 브라우저에서 열어서(정적 서버 필요 없음, `apps/2048/index.html`을 직접 파일로 열거나 임시 로컬 서버 사용) 다음을 직접 조작해 확인한다:
   - 방향키로 몇 번 이동해 타일이 합쳐지고 점수가 오르는지
   - 새 게임 버튼으로 재시작되는지
   - 모바일 뷰포트(예: 375px)로 리사이즈했을 때 레이아웃이 정상인지
4. 문제를 발견하면 `apps/2048/` 안의 파일만 직접 수정해서 고친다. 고치기 애매하거나 범위를 벗어나는 큰 이슈면 고치지 말고 review.md에 이슈로만 남긴다.
5. 점검 결과를 `apps/2048/review.md`에 정리한다: 확인한 항목 목록, 발견한 문제와 조치 여부(수정함/미수정), 브라우저로 확인한 결과.

## 하지 말아야 할 것
- `apps/2048/` 밖의 어떤 파일도 만들거나 수정하지 않는다.
- git 커밋을 하지 않는다 (커밋은 이후 Embed 단계에서 처리한다).
- spec.md에 없는 새 기능을 추가하지 않는다.

## 완료 조건
`apps/2048/review.md` 작성 완료, 발견한 문제는 가능한 선에서 직접 수정 완료. 완료 후 핵심 결과를 요약해서 보고할 것 (문제 있었는지, 고쳤는지, 최종 상태가 정상인지 — 300단어 이내).
