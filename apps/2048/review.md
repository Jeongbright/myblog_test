# 2048 게임 리뷰 결과

리뷰 대상: `apps/2048/index.html`, `apps/2048/style.css`, `apps/2048/script.js`
비교 기준: `apps/2048/spec.md`
방법: 코드 정독 + 로직 단위 테스트(Node로 병합 알고리즘 분리 실행) + 로컬 정적 서버(`127.0.0.1:8791`)를 띄워 실제 브라우저(내장 Browser 패널)에서 조작 확인.

## 점검 항목 체크리스트

- [x] 문법 오류 / 런타임 참조 오류 여부 — 없음. 콘솔 에러 없음(데스크톱/모바일 뷰포트, localStorage 차단 상황 모두 확인).
- [x] 4방향 이동/병합 로직 — `getLine`/`setLine`으로 방향별 좌표를 매핑하고 `slideAndMergeLeft`로 압축·병합(spec은 회전 방식을 제안하지만, 구현은 방향별 인덱싱 방식으로 동일한 결과를 내는 대안 — 문제 없음).
- [x] 3연쇄 병합 등 엣지 케이스 — `slideAndMergeLeft`만 추출해 Node에서 단위 테스트:
  - `[2,2,2,2] → [4,4]` (o), `[4,4,4,4] → [8,8]` (o)
  - `[8,2,2,2] → [8,4,2]` (트리플 병합 없음, o)
  - `[2,4,4,2] → [2,8,2]` (재병합 없음, o)
  모두 스펙대로 동작.
- [x] 게임오버 판정 — 빈 칸 없고 상/하/좌/우 인접 동일값이 전혀 없을 때만 `isOver=true`. 로직 확인, 정상.
- [x] 점수/최고점수 계산 및 localStorage — 병합 점수 합산 정상(실측: 2+2 병합 시 SCORE 4로 정확히 반영). `loadBestScore`/`saveBestScore` 모두 try/catch로 감싸져 있음. `window.localStorage`가 접근 시 예외를 던지도록 강제로 오버라이드한 뒤 이동/새 게임을 실행해도 콘솔 에러 없이 정상 동작 확인(프라이빗 모드 대응 OK).
- [x] 키보드(방향키, WASD 추가 지원) — 실제 키 입력으로 이동/병합/점수 반영 확인.
- [x] 모바일 터치 스와이프 — `TouchEvent`를 직접 디스패치해 스와이프 우측 이동을 재현, 타일이 올바르게 이동함을 확인.
- [x] 모바일 폭 반응형(375px) — 뷰포트를 375x812로 전환해 확인. 가로 스크롤 없음(`document.documentElement.scrollWidth === innerWidth`), 보드/헤더/버튼 레이아웃 정상.
- [x] 데스크톱 폭에서 보드 오버플로 여부 — `.board-wrap`에 `width: min(92vw,500px)` 외에 `max-width: 100%`가 있어 부모(`.game-2048`, 패딩 포함 컨텐츠 폭 468px)를 넘지 않음을 실측 확인(뷰포트 966px에서 보드 실제 폭 468px, 문서 스크롤폭이 뷰포트 폭보다 작음 → 오버플로 없음). 처음엔 버그로 의심했으나 `max-width:100%`가 이를 방지하고 있어 실제로는 문제 없음.
- [x] 다크 모드(`prefers-color-scheme: dark`) — 시스템 다크 모드에서 실제 렌더링 확인.

## 발견한 문제와 조치

### 수정함: 다크 모드에서 제목/안내 문구 대비(contrast) 부족
- **증상**: 다크 모드 전환 시 `.game-title`, `.game-hint`가 `--text-dark`(#776e65, 라이트 모드용 갈색)를 그대로 사용해 어두운 배경(`--body-bg: #1c1d22`)과 대비가 낮았음(계산상 대비비 약 3.4:1, `.game-hint`는 `opacity:0.85`까지 겹쳐 있어 일반 텍스트 기준 WCAG AA(4.5:1) 미달). 스펙 5장에 "스코어박스, 버튼, 힌트 텍스트 색상만 다크 배경에 어울리게 조정"이라고 명시돼 있었으나 실제 구현에는 반영되어 있지 않았음.
- **조치**: `style.css`에 `--heading-text`, `--hint-text` 변수를 추가해 `.game-title`/`.game-hint`에 적용하고, 다크 모드 미디어쿼리에서만 각각 `#ece7e1`, `#ccc5ba`로 밝게 재정의함. `--text-dark`(타일/오버레이 텍스트에 쓰이는 값)는 스펙 의도대로 건드리지 않아 타일 팔레트에는 영향 없음. 수정 후 실제 다크 모드 스크린샷으로 가독성 개선 확인.
- **수정 파일**: `apps/2048/style.css`만 수정 (`index.html`, `script.js`는 변경 없음).

### 문제 없음으로 확인(버그 아님)
- `.board-wrap`의 `width: min(92vw, 500px)`만 보면 데스크톱 폭에서 부모 컨텐츠 폭(468px)을 넘어서는 것처럼 보였으나, 같은 규칙에 있는 `max-width: 100%`가 이를 부모 폭으로 clamp하고 있어 실제로는 오버플로가 발생하지 않음(직접 측정으로 재확인). 코드 변경 불필요.
- 문서 레벨 `keydown` 리스너가 항상 `preventDefault()` 후 `move()`를 호출하는 구조라, 오버레이 버튼에 포커스가 있어도 화살표 키가 버튼 포커스 이동 대신 타일 이동으로 처리됨. 스펙 7장에 "향후 확인 포인트(참고용)"로 언급된 사항이나, 2048류 게임에서는 일반적으로 기대되는 동작이라 결함으로 보지 않음. 별도 수정하지 않음.

## 브라우저 실측 결과 요약
1. 방향키(←/↑/→/↓) 연속 입력 → 타일 이동/병합, SCORE 0→4, BEST 0→4 정상 갱신.
2. "새 게임" 버튼 클릭 → 보드 초기화(SCORE 0), BEST는 유지됨(로컬스토리지 정상).
3. 375px 모바일 뷰포트 → 레이아웃 깨짐 없음, 가로 스크롤 없음.
4. 터치 스와이프(TouchEvent 시뮬레이션) → 방향에 맞게 타일 이동 확인.
5. `localStorage` 접근 시 예외를 던지도록 강제한 상태에서 이동/새 게임 실행 → 콘솔 에러 없이 정상 동작(프라이빗 모드 대응 확인).
6. 다크 모드 활성 상태에서 스크린샷 비교 → 수정 전 제목/안내 문구 저대비 확인 → 수정 후 가독성 개선 확인.
7. 오버레이(승리/게임오버) 마크업에 임의로 메시지를 주입해 다크 배경 위에서도 오버레이 카드(크림색 배경 + 진한 텍스트)가 정상적으로 잘 보이는지 확인.

## 결론
`spec.md` 대비 핵심 로직(이동/병합/3연쇄 방지/게임오버/점수/저장/입력 처리/반응형)은 모두 스펙대로 정확히 구현되어 있었음. 유일하게 발견된 실질적 문제는 다크 모드에서 제목·안내 문구의 색상 대비 부족이었고, `style.css`만 수정해 해결함. `index.html`, `script.js`는 변경하지 않았음(문제 없음). 최종 상태는 정상.
