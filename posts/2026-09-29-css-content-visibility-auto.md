긴 목록 페이지나 스크롤이 긴 문서는 처음 렌더링할 때 화면 밖 콘텐츠까지 전부 레이아웃과 페인트를 계산합니다. `content-visibility: auto`를 쓰면 브라우저가 화면 밖 영역의 렌더링 작업을 뷰포트 근처로 올 때까지 건너뛰어서 초기 렌더링 비용을 크게 줄일 수 있습니다.

## 기본 사용법

렌더링 비용이 큰 섹션(카드 목록의 각 항목, 긴 게시글의 각 블록 등)에 적용합니다.

```css
.card {
  content-visibility: auto;
  contain-intrinsic-size: auto 320px;
}
```

`contain-intrinsic-size`는 아직 렌더링하지 않은 요소의 예상 높이를 지정해 스크롤바가 요소 개수에 따라 들쭉날쭉해지는 것을 막아줍니다. 실제 콘텐츠 높이와 크게 다르면 스크롤 점프가 생기니, 대략적인 평균 높이를 넣어주는 게 좋습니다.

## 효과 확인하기

개발자 도구의 Performance 탭에서 레이아웃/페인트 구간을 확인하면, `content-visibility: auto`를 적용하기 전보다 초기 렌더링에 걸리는 시간이 뚜렷하게 줄어드는 것을 볼 수 있습니다. 특히 수백 개의 항목이 있는 목록에서 효과가 큽니다.

## 주의할 점

`content-visibility: hidden`과 달리 `auto`는 요소가 뷰포트에 가까워지면 자동으로 다시 렌더링되므로 별도의 JS 없이도 쓸 수 있습니다. 다만 `Ctrl+F` 같은 브라우저 내장 찾기 기능이나 접근성 트리 계산 시점에 영향을 줄 수 있으니, 검색이 반드시 되어야 하는 콘텐츠라면 적용 전에 실제 브라우저에서 동작을 확인해보는 것이 안전합니다.
